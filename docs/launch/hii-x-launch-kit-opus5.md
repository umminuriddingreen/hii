# HII X launch kit

Date: 2026-07-30
Status: working copy; do not publish until the named proof gates and cohort terms
are complete.

This kit was developed with Claude Opus 5 and then checked against HII's live
product receipts. Opus supplied the launch structure. HII's verified state
decides every claim.

## Positioning

> HII is a local-first spatial workspace where you select the context, state
> the intent, approve a bounded run, and get editable work plus a receipt you
> can inspect and reuse.

Short form:

> Intent in. Receipt out.

HII is the interface where a person, their information, and bounded agents work
together. It does not “make work meaningful,” replace the person's tools, or
turn their Mac into an unbounded autonomous loop.

### Boundary

“Autonomous” often means nobody can tell you what it touched.

HII shows the local step budget, workspace boundary, and external-action
boundary before the run starts. You approve the work, then AII owns the bounded
execution.

`[approval clip]`

### Artifact

The output of an AI run should not be a filename buried in a chat.

In HII it returns as an editable object beside the references and intent that

### Receipt

Six weeks later, “why is this like this?” should have an answer.

HII keeps a receipt with the intent, approved context, checks, artifacts, and
run identity.

Provenance, not magic.

`[receipt clip]`

### Honest gap

The first HII demo workspace became crowded enough that a later draft could
cover a completed run.

That is not a marketing problem. It is a product defect.

The useful thing about yesterday's agent session is not the transcript.

## Claim boundary

| Verified now | Careful inference | Do not publish |
| --- | --- | --- |
| Local-first spatial workspace on Mac | A bounded, selected context can reduce surprises | Total privacy or “nothing ever leaves your Mac” |
| Explicit context and run approval | Approval-first design | Safe, risk-free, or impossible to misuse |
| Capability, step, workspace, external, and model boundaries | Reviewable scope | Per-tool approval unless the UI actually shows it |
| Five-step governed lifecycle | Legible agent work | Autonomous, infinite, or works while you sleep |
| Editable receipt-linked text artifacts | Direct manipulation inspired by canvas tools | Replaces Figma, Miro, Freeform, Cursor, or Claude |
| Checks, proof records, and receipts | Human-readable provenance | Proof of correctness, audit-ready, or no hallucinations |
| Stop, cancellation, and interrupted-run reconciliation | Operator control | Every cancellation preserves a usable partial artifact |
| Operator-reviewed capability drafts | Reusable after review | Self-improving or automatically learns from you |
| Named Scenes, Map, contact sheets, local knowledge, runtime health, and full local CI | A growing workspace can remain navigable | First-of-kind, unprecedented, or guaranteed viral |
| Setup is real | Guided onboarding | Zero setup or one-click |

## Product changes that increase demo clarity

1. **Run-group isolation and focus.** Map focus must raise the requested object.
   New follow-up and result groups must choose a collision-free lane. Prove
   three sequential runs without occlusion.
2. **One glanceable receipt.** Make boundary, lifecycle result, checks, changed
   artifacts, and duration readable at phone-video scale without opening raw
   logs.
3. **Boundary change awareness.** After repeated runs in one Scene, make any
   changed workspace or external boundary obvious so approval does not become
   theater.

## Distribution loop

Do not try to manufacture a new “AI hype cycle.” Continue the useful part of
the Cursor and OpenClaw pattern: frequent visible proof, a recognizable point
of view, and workflows other people can reproduce.

Weekly loop:

1. Name one real creative job and its acceptance check.
2. Record the real run, including failure.
3. Post the shortest transformation that includes its receipt.
4. Ask for one concrete next action.
5. Publish the honest gap.
6. Close that gap in the next product clip.

Virality is not a product gate. Specific first-job replies, completed first
wins, second use within seven days, paid activations, and credited cohort work
are.

## Opus 5 red-team corrections

The raw Opus proposal was not copied blindly. These suggestions were removed
because current HII proof does not support them:

- Approval becoming enabled only after scrolling the boundary card.
- A complete per-tool permission list in the current approval UI.
- Every cancelled run returning a useful partial artifact.
- A guaranteed 42-second continuous run.
- Deleting a run also deleting its durable receipt.
- Absolute privacy, safety, correctness, or viral claims.

Model used for the external critique: `claude-opus-5`.
