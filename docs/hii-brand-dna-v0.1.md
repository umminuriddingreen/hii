# HII Brand DNA v0.1

## Direction

HII is a local-first control plane for verified agent work.

The current wedge is not a broad creator workspace or marketplace. It is the daily operational loop:

> Human intent -> bounded agent/tool work -> logs/proof -> verification -> receipt -> reusable capability.

Product sentence:

> HII turns current local context into the next approved, verifiable step.

Long-term vision:

> HII makes useful agent work inspectable, repeatable, and safe enough to trust.

## Reference Logic

The useful reference is operational transparency: give people the playbook, show the work, and ask before crossing risky boundaries.

- Make the path public and teachable: turn hidden agent process into A-to-Z steps.
- Treat naming as an anchor: every surface name should explain why it exists.
- Keep references visible: show sources, inputs, constraints, and why a next move was prepared.
- Keep proposal, approval, execution, and proof separate.
- Use quotes, labels, receipts, and catalog structure as product grammar.
- Prefer one reliable daily loop over many unfinished surfaces.

## Brand DNA

- Positioning: local-first verified agent work, not a chatbot and not remote compute magic.
- Core feeling: calm, visible, and operational.
- First audience: the operator using this workstation to coordinate plans, goals, businesses, agents, and local tools.
- Promise: HII understands context, prepares the next move, asks approval, acts locally when allowed, and preserves proof.
- Visual formula: Apple calm + Codex trust + local systems + receipt grammar.
- Tone: short, direct, factual, human. No corporate AI jargon.
- Internal mantra: Always proceed to the safest next step.

## UX/UI Laws

1. No Dead Ends. Every answer must produce a next action, saved artifact, approval card, usable draft, or clear blocker.
2. Context Is Visible. Show what HII knows: repo state, jobs, board tasks, capabilities, recent decisions, runtime files, auth state, and blockers.
3. Agency Has Gates. HII can prepare freely, but asks before money, external writes, auth, deletion, publishing, pushing, or irreversible actions.
4. Local First. Runtime state stays under `~/.hii`; product code stays in `/Users/ummi/hii`; external calls require explicit approval.
5. Light First, Alive Underneath. Default shell stays bright and readable; motion, status, and agent activity prove intelligence is running.
6. Internet Texture, Not Noise. Command labels, status chips, receipts, and tiny system details can carry personality without blocking work.
7. Proof Beats Magic. Show sources, logs, diffs, receipts, and why a recommendation is next.
8. Commands Are Shortcuts. The default product should expose the loop; the console remains the power layer.

## First Product

HII Today.

The first screen should make the operator understand in five seconds:

> I can see the current state, approve the next move, and get proof back.

Core modules:

- Today Inbox: next actions from HII context, OG status, jobs, and board tasks.
- Context Rail: repo, runtime, capability registry, guardrails, stale jobs, and blockers.
- Approval Queue: Approve, Edit, Skip, with source context and risk label.
- Proof Recommender: checks, logs, receipts, and artifacts that can close the loop.
- Board Receipts: local append-only tasks under `~/.hii/board/tasks.jsonl`.
- Job Receipts: local append-only capability jobs under `.hii/capability-jobs.jsonl`.
- Console: live agent, terminal, runner, and proof stream.

## First Workflow

Input:

- Dirty repo state
- Recent capability jobs
- Board tasks
- Capability registry
- Runtime guardrails
- User request

HII returns:

- 1 ranked next action
- 1 approval card
- 1 verification plan
- 1 local execution boundary
- 1 proof checklist
- 1 receipt target

Approval copy:

> I prepared the next local move. Want me to run it and save the receipt?

Buttons:

- Approve
- Edit
- Skip

## Visual Rules

- Primary palette: warm white, graphite, soft blue, soft green, silver gray.
- Accent palette: electric blue, acid green, violet, chrome highlights, used sparingly.
- Typography: clean sans for product; mono for commands, receipts, and state.
- Shapes: mostly sharp or 6-8px radius; avoid over-rounded SaaS bubbles.
- Motion: alive bars, breathing status, streaming task cards, smooth state transitions.
- Texture: browser chrome, scanner lines, early-web buttons, tiny system icons. Use as seasoning, not wallpaper.
- Imagery: local systems, architecture diagrams, proof artifacts, screenshots, and operational maps.

## Test Plan

- 5-second test: user says "this shows what HII wants to do next," not "chatbot" or "random dashboard."
- Trust test: user can identify what HII wants to do, why, and what requires approval.
- Locality test: user can see what is local and what would be external.
- Proof test: completed work points to logs, receipts, diffs, artifacts, or command output.
- Productivity test: no text overlap, no decorative graphics blocking work, no hidden next step.
- Brand consistency test: every screen should satisfy calm, visible, contextual, agentic, and human.
